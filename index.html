Part 1

Motivation

Why write LLM training in raw C/CUDA?

The Pitch

llm.c trains GPT-2 / GPT-3 in "simple, pure C/CUDA with no need for 245MB of PyTorch or 107MB of cPython."

No heavyweight dependencies. No PyTorch, no Python interpreter, no autograd engine — just a C compiler and (for the GPU path) CUDA.

~1,000 readable lines. The CPU reference, train_gpt2.c, is a single file you can read end-to-end in an afternoon.

Full control & fast compile. Every byte of memory and every FLOP is explicit. No framework magic between you and the hardware.

A clean reference. It shows exactly what PyTorch does under the hood — forward, backward and the optimiser, written out by hand.

The goal: reproduce GPT-2 (124M) from scratch, then scale the same code to multi-GPU and multi-node.

Build & Run — the Whole Toolchain

# CPU reference (single C file, OpenMP-parallelised)
make train_gpt2
OMP_NUM_THREADS=8 ./train_gpt2

# GPU, fp32 reference
make train_gpt2fp32cu
./train_gpt2fp32cu

# GPU, mixed precision (BF16) — the fast path
make train_gpt2cu
./train_gpt2cu

That's it. No pip install, no requirements.txt, no virtual environment. A download_starter_pack.sh script fetches the tokenizer, pretrained GPT-2 weights and the tokenised dataset shards, and you are training.

Part 2

Layout & Parameter Tensors

One malloc, a struct of pointers, and a config

GPT2Config — Six Integers

typedef struct {
    int max_seq_len;       // e.g. 1024
    int vocab_size;        // 50257
    int padded_vocab_size; // 50304 (padded to a nice multiple)
    int num_layers;        // 12 for GPT-2 124M
    int num_heads;         // 12
    int channels;          // 768 (the embedding dim, "C")
} GPT2Config;

The entire architecture is six integers. Everything else — tensor sizes, loop bounds, offsets — is derived from these. Note padded_vocab_size: the vocab is padded (50257 → 50304) so matmuls hit aligned, GPU-friendly sizes.

ParameterTensors — 16 Named Weights

#define NUM_PARAMETER_TENSORS 16
typedef struct {
    float* wte;      float* wpe;      // token + position embeddings
    float* ln1w;     float* ln1b;     // layernorm 1 (weight, bias)
    float* qkvw;     float* qkvb;     // fused Q,K,V projection
    float* attprojw; float* attprojb; // attention output projection
    float* ln2w;     float* ln2b;     // layernorm 2
    float* fcw;      float* fcb;      // MLP up-projection (4C)
    float* fcprojw;  float* fcprojb;  // MLP down-projection
    float* lnfw;     float* lnfb;     // final layernorm
} ParameterTensors;

Sixteen float* fields. The per-layer tensors (ln1w, qkvw, …) are sized L * … so all layers live contiguously inside one tensor. wte doubles as the output classifier (weight tying).

One Big Buffer, Pointers Into It

float* malloc_and_point_parameters(ParameterTensors* params,
                                   size_t* param_sizes) {
    size_t num_parameters = 0;
    for (size_t i = 0; i < NUM_PARAMETER_TENSORS; i++)
        num_parameters += param_sizes[i];
    // a SINGLE allocation holds every weight in the model
    float* params_memory =
        (float*)mallocCheck(num_parameters * sizeof(float));
    // point each named tensor at its slice of the buffer
    float** ptrs[] = {¶ms->wte, ¶ms->wpe, /* ...16... */};
    float* iter = params_memory;
    for (size_t i = 0; i < NUM_PARAMETER_TENSORS; i++) {
        *(ptrs[i]) = iter;
        iter += param_sizes[i];
    }
    return params_memory;
}

Why one buffer? The optimiser can sweep all weights in a single flat loop; the whole model can be saved, loaded or copied to the GPU with one memcpy; and there is exactly one thing to free. The named pointers are just typed views into that flat array.

A single contiguous float* — every weight in GPT-2 laid end to end (widths ≈ relative parameter counts).

Loading weights: a short Python script (train_gpt2.py) exports a PyTorch GPT-2 checkpoint to a flat gpt2_124M.bin — header (config) followed by the raw parameter blob in this exact order. The C code reads the header, computes the same sizes with fill_in_parameter_sizes(), then freads the blob straight into the buffer.

fill_in_parameter_sizes — Sizes from Config

void fill_in_parameter_sizes(size_t* param_sizes, GPT2Config config) {
    size_t Vp = config.padded_vocab_size, C = config.channels;
    size_t maxT = config.max_seq_len, L = config.num_layers;
    param_sizes[0] = Vp * C;          // wte
    param_sizes[1] = maxT * C;        // wpe
    param_sizes[2] = L * C;           // ln1w
    param_sizes[3] = L * C;           // ln1b
    param_sizes[4] = L * (3 * C) * C; // qkvw  (fused Q,K,V)
    param_sizes[5] = L * (3 * C);     // qkvb
    // ... fcw is L * (4*C) * C, etc.
}

Activations get the same treatment: ActivationTensors has NUM_ACTIVATION_TENSORS 23 fields (encoded, ln1, qkv, preatt, att, fch_gelu, logits, probs, losses, …) backed by their own single buffer, sized once the batch B and sequence length T are known.

Part 3

The Forward Pass Kernels

Each layer is a plain C function over float arrays

encoder_forward — Token + Position Embeddings

void encoder_forward(float* out, int* inp, float* wte, float* wpe,
                     int B, int T, int C) {
    for (int b = 0; b < B; b++)
        for (int t = 0; t < T; t++) {
            float* out_bt = out + b * T * C + t * C;
            int ix = inp[b * T + t];          // the token id
            float* wte_ix = wte + ix * C;     // its embedding row
            float* wpe_t  = wpe + t * C;      // the position row
            for (int i = 0; i < C; i++)
                out_bt[i] = wte_ix[i] + wpe_t[i];
        }
}

Pointer arithmetic is the indexing. b*T*C + t*C walks the flat activation buffer; a token id ix selects a row of wte; the position selects a row of wpe; the two are summed. That single addition is the embedding layer.

layernorm_forward — Normalise Each Token

void layernorm_forward(float* out, float* mean, float* rstd,
                       float* inp, float* weight, float* bias,
                       int B, int T, int C) {
    float eps = 1e-5f;
    for (int b = 0; b < B; b++) {
        for (int t = 0; t < T; t++) {
            float* x = inp + b * T * C + t * C;
            float m = 0.0f;                          // 1. mean
            for (int i = 0; i < C; i++) m += x[i];
            m = m/C;
            float v = 0.0f;                          // 2. variance
            for (int i = 0; i < C; i++) {
                float xshift = x[i] - m;
                v += xshift * xshift;
            }
            v = v/C;
            float s = 1.0f / sqrtf(v + eps);         // 3. 1/std
            float* out_bt = out + b * T * C + t * C;
            for (int i = 0; i < C; i++) {
                float n = (s * (x[i] - m));          // normalise
                out_bt[i] = n * weight[i] + bias[i]; // scale + shift
            }
            mean[b * T + t] = m;   // cached for the backward pass
            rstd[b * T + t] = s;
        }
    }
}

Mean and rstd are written out, not thrown away — the backward pass needs them, so caching beats recomputing.

matmul_forward & the Linear Layers

void matmul_forward(float* out, const float* inp,
                    const float* weight, const float* bias,
                    int B, int T, int C, int OC);
// out[b,t,:] = inp[b,t,:] @ weight^T + bias
//   (B,T,C) x (OC,C)^T  ->  (B,T,OC)

Every projection — QKV, the attention output, both MLP layers, the final classifier — is one matmul_forward call. On CPU it is a triple loop with an #pragma omp parallel for; this single kernel is also where almost all the FLOPs (and on GPU, all the cuBLAS/cuBLASLt calls) live.

void gelu_forward(float* out, float* inp, int N) {
    for (int i = 0; i < N; i++) {
        float x = inp[i];
        float cube = 0.044715f * x * x * x;
        out[i] = 0.5f * x * (1.0f +
                 tanhf(GELU_SCALING_FACTOR * (x + cube)));
    }
}
void residual_forward(float* out, float* inp1, float* inp2, int N) {
    for (int i = 0; i < N; i++) out[i] = inp1[i] + inp2[i];
}

attention_forward — q·kᵀ, scale, mask, softmax, ·v

void attention_forward(float* out, float* preatt, float* att,
                       float* inp, int B, int T, int C, int NH) {
    int C3 = C*3; int hs = C / NH;        // head size
    float scale = 1.0 / sqrtf(hs);
    #pragma omp parallel for collapse(3)
    for (int b = 0; b < B; b++)
     for (int t = 0; t < T; t++)
      for (int h = 0; h < NH; h++) {
        float* query_t   = inp + b*T*C3 + t*C3 + h*hs;
        float* preatt_bth = preatt + b*NH*T*T + h*T*T + t*T;
        float* att_bth    = att    + b*NH*T*T + h*T*T + t*T;
        // 1. q . k^T for t2 <= t  (causal: never look ahead)
        float maxval = -10000.0f;
        for (int t2 = 0; t2 <= t; t2++) {
            float* key_t2 = inp + b*T*C3 + t2*C3 + h*hs + C;
            float val = 0.0f;
            for (int i = 0; i < hs; i++) val += query_t[i]*key_t2[i];
            val *= scale;
            if (val > maxval) maxval = val;
            preatt_bth[t2] = val;
        }
        // 2. softmax (subtract max for stability)
        float expsum = 0.0f;
        for (int t2 = 0; t2 <= t; t2++) {
            float expv = expf(preatt_bth[t2] - maxval);
            expsum += expv; att_bth[t2] = expv;
        }
        float expsum_inv = expsum == 0.0f ? 0.0f : 1.0f/expsum;
        for (int t2 = 0; t2 < T; t2++)
            att_bth[t2] = (t2 <= t) ? att_bth[t2]*expsum_inv : 0.0f;
        // 3. weighted sum of values -> output
        float* out_bth = out + b*T*C + t*C + h*hs;
        for (int i = 0; i < hs; i++) out_bth[i] = 0.0f;
        for (int t2 = 0; t2 <= t; t2++) {
            float* value_t2 = inp + b*T*C3 + t2*C3 + h*hs + C*2;
            float a = att_bth[t2];
            for (int i = 0; i < hs; i++) out_bth[i] += a * value_t2[i];
        }
      }
}

The causal mask isn't a separate -inf matrix — the inner loops simply run t2 <= t. Q, K and V share one fused inp buffer of stride C3 = 3C: keys at offset +C, values at +2C.

The Head: Logits → Softmax → Cross-Entropy

void softmax_forward(float* probs, float* logits,
                     int B, int T, int V, int Vp) {
    #pragma omp parallel for collapse(2)
    for (int b = 0; b < B; b++)
      for (int t = 0; t < T; t++) {
        float* logits_bt = logits + b*T*Vp + t*Vp;
        float* probs_bt  = probs  + b*T*Vp + t*Vp;
        float maxval = -10000.0f;
        for (int i = 0; i < V; i++)
            if (logits_bt[i] > maxval) maxval = logits_bt[i];
        float sum = 0.0f;
        for (int i = 0; i < V; i++) {
            probs_bt[i] = expf(logits_bt[i] - maxval); sum += probs_bt[i];
        }
        for (int i = 0; i < V;  i++) probs_bt[i] /= sum;
        for (int i = V; i < Vp; i++) probs_bt[i] = 0.0f; // padded vocab
    }
}
void crossentropy_forward(float* losses, float* probs, int* targets,
                          int B, int T, int Vp) {
    for (int b = 0; b < B; b++)
      for (int t = 0; t < T; t++) {
        float* probs_bt = probs + b*T*Vp + t*Vp;
        int ix = targets[b*T + t];
        losses[b*T + t] = -logf(probs_bt[ix]); // negative log-likelihood
    }
}

The padded vocab entries (V..Vp) are explicitly zeroed so they can never receive probability mass. The loss is the mean of -log(probs[target]) over all B·T positions.

There is no autograd graph. grads_memory is a second buffer with the identical layout to params_memory (and a ParameterTensors grads struct pointing into it). Because the layouts match byte-for-byte, the optimiser later updates every weight with one flat loop over the two buffers.

layernorm_backward — The Chain Rule, Spelled Out

void layernorm_backward(float* dinp, float* dweight, float* dbias,
                        float* dout, float* inp, float* weight,
                        float* mean, float* rstd, int B, int T, int C) {
    for (int b = 0; b < B; b++)
      for (int t = 0; t < T; t++) {
        float* dout_bt = dout + b*T*C + t*C;
        float* inp_bt  = inp  + b*T*C + t*C;
        float* dinp_bt = dinp + b*T*C + t*C;
        float mean_bt = mean[b*T+t], rstd_bt = rstd[b*T+t];
        // two reduction terms needed by the normalisation gradient
        float dnorm_mean = 0.0f, dnorm_norm_mean = 0.0f;
        for (int i = 0; i < C; i++) {
            float norm_bti = (inp_bt[i] - mean_bt) * rstd_bt;
            float dnorm_i  = weight[i] * dout_bt[i];
            dnorm_mean      += dnorm_i;
            dnorm_norm_mean += dnorm_i * norm_bti;
        }
        dnorm_mean      /= C;
        dnorm_norm_mean /= C;
        for (int i = 0; i < C; i++) {
            float norm_bti = (inp_bt[i] - mean_bt) * rstd_bt;
            float dnorm_i  = weight[i] * dout_bt[i];
            dbias[i]   += dout_bt[i];            // += : accumulate
            dweight[i] += norm_bti * dout_bt[i]; //      over B,T
            float dval = dnorm_i - dnorm_mean
                         - norm_bti * dnorm_norm_mean;
            dinp_bt[i] += dval * rstd_bt;
        }
    }
}

Note += everywhere: gradients accumulate. dweight/dbias sum contributions from every (b,t); the cached mean/rstd from the forward pass are reused rather than recomputed. This is hand-derived calculus — the price of having no autograd.

matmul_backward — One Forward, Three Grads

void matmul_backward(float* dinp, float* dweight, float* dbias,
                     const float* dout, const float* inp,
                     const float* weight, int B, int T, int C, int OC);
//  dinp   += dout @ weight       (gradient flowing to the input)
//  dweight += dout^T @ inp       (gradient of the weight matrix)
//  dbias  += sum over B,T of dout

A single matmul in the forward pass becomes three matmul-shaped reductions in the backward pass: one for the input, one for the weights, one for the bias. The same pattern repeats for QKV, the attention projection, both MLP layers and the classifier head.

The mirror principle: encoder_backward, attention_backward, gelu_backward, residual_backward and crossentropy_softmax_backward each undo their forward twin — the backward pass is literally the forward list, reversed.

gpt2_update — AdamW, By Hand

void gpt2_update(GPT2 *model, float learning_rate, float beta1,
                 float beta2, float eps, float weight_decay, int t) {
    if (model->m_memory == NULL) { // lazily allocate moment buffers
        model->m_memory = calloc(model->num_parameters, sizeof(float));
        model->v_memory = calloc(model->num_parameters, sizeof(float));
    }
    for (size_t i = 0; i < model->num_parameters; i++) {
        float param = model->params_memory[i];
        float grad  = model->grads_memory[i];
        // 1st & 2nd moment running averages
        float m = beta1*model->m_memory[i] + (1.0f-beta1)*grad;
        float v = beta2*model->v_memory[i] + (1.0f-beta2)*grad*grad;
        // bias correction
        float m_hat = m / (1.0f - powf(beta1, t));
        float v_hat = v / (1.0f - powf(beta2, t));
        model->m_memory[i] = m;
        model->v_memory[i] = v;
        // decoupled weight decay (the "W" in AdamW)
        model->params_memory[i] -= learning_rate *
            (m_hat / (sqrtf(v_hat) + eps) + weight_decay * param);
    }
}

One flat loop over every parameter — possible only because params, grads, m and v all share the same layout. This is exactly what torch.optim.AdamW does, with nothing hidden.

main() — The Training Loop

// build the model from a PyTorch-exported checkpoint
GPT2 model;
gpt2_build_from_checkpoint(&model, "gpt2_124M.bin");

// dataloaders over tokenised .bin shards
DataLoader train_loader, val_loader;
dataloader_init(&train_loader, train_pattern, B, T, /*...*/);

for (int step = 0; step <= 40; step++) {
    dataloader_next_batch(&train_loader);          // inputs, targets
    gpt2_forward(&model, train_loader.inputs,
                 train_loader.targets, B, T);       // -> mean loss
    gpt2_zero_grad(&model);                         // memset grads to 0
    gpt2_backward(&model);                          // fill grads_memory
    gpt2_update(&model, 1e-4f, 0.9f, 0.999f,
                1e-8f, 0.0f, step+1);               // AdamW step
    printf("step %d: train loss %f\n", step, model.mean_loss);
}

The four-line heart of training: gpt2_forward runs the kernel chain and computes the loss; gpt2_zero_grad memsets the grad buffer; gpt2_backward runs the reversed chain; gpt2_update steps AdamW. The dataloader just freads uint16 tokens from .bin shards.

Part 6

CUDA & Scaling

From a 1,000-line reference to faster-than-PyTorch

Porting the Kernels to CUDA

Same kernels, GPU threads. Each *_forward/*_backward becomes a CUDA kernel: the (b,t) / (b,t,h) loops map onto a grid of threads instead of an OpenMP loop.

Mixed precision (BF16). The fast path stores activations/weights in bfloat16, with fp32 master state, for ~2× throughput and lower memory.

cuBLASLt matmuls. The hand-written matmul is replaced by fused cuBLASLt GEMMs (matmul + bias + GELU epilogue).

Flash attention. The attention kernel can use cuDNN's flash attention — never materialising the full T×T score matrix (off by default to keep compile times down).

# cuDNN flash-attention build
make train_gpt2cu USE_CUDNN=1
./train_gpt2cu

Multi-GPU & Multi-Node

# Data-parallel across N GPUs on one box (NCCL all-reduce of grads)
mpirun -np 8 ./train_gpt2cu

# Multi-node: same binary, launched across machines via MPI
#  (also supports a shared filesystem or TCP sockets for init)

NCCL handles the gradient all-reduce between GPUs; MPI launches and coordinates processes across nodes. The single-buffer design pays off again: one flat grads_memory is exactly one all-reduce.

Key Takeaways

1

A whole LLM trainer fits in ~1,000 lines of C. One config struct, one parameter buffer, a handful of kernels, their hand-written backward twins, and AdamW — no PyTorch, no Python, no autograd engine.

2

Frameworks aren't magic. Reading matmul_backward or gpt2_update shows exactly what loss.backward() and optimizer.step() do — the maths is all there, written out by hand.

3

Simple can also be fast. The same design, ported to CUDA with BF16, cuBLASLt and flash-attention, reproduces GPT-2 and runs ~7% faster than PyTorch — scaling to multi-GPU (NCCL) and multi-node (MPI).
